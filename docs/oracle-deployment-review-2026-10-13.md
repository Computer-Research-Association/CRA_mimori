## 수정 및 운영 반영

1. 방문자별 요청 제한 복구: nginx가 X-Forwarded-For/Proto를 덮어쓰고 Flask는 nginx 한 단계만 신뢰하게 했다. 이전에는 request.remote_addr가 nginx IP여서 사용자들이 제한을 공유할 수 있었다. 적용 방식은 [Werkzeug ProxyFix 공식 문서](https://werkzeug.palletsprojects.com/en/stable/middleware/proxy_fix/)의 프록시 개수 제한에 따랐다. API의 localhost 제한은 유지해야 한다.
2. CORS 허용 목록에 현재 서비스 도메인을 추가했다. 실제 프론트는 동일 출처 프록시를 사용하므로 기존 도메인 누락이 현재 접속 장애의 원인은 아니었다.
3. 순위 API에 집계일을 추가하고 순위 행과 상세 트렌드에 날짜를 표시했다. 제목을 “저장된 트렌드 순위”로 고치고, 서로 다른 집계일의 점수임을 안내한다.
4. “이미 분석까지 끝나 있어요”, “내일 순위 합류”라는 보장성 안내를 실제 동작에 맞게 수정했다.

변경 파일 5개를 원본 해시 대조 후 백업·배포했다. 웹 이미지를 재빌드하고 API와 웹만 재시작했다. 데이터와 scheduler는 그대로 유지했다. Git 커밋·push는 하지 않았다.

## 검증

- API 관련 pytest 36개 통과. `uv run --with pytest python -m pytest ...`로 실행.
- 프론트 관련 Vitest 28개 통과. 기존 비동기 테스트의 act 경고는 남아 있음.
- 로컬 및 서버 Vite 프로덕션 빌드 성공. nginx 설정 검사 성공.
- 배포 후 홈페이지, health, keywords, trend HTTP 200. 관리자 stats는 인증 없이 401.
- 운영 nginx 경유로 빈 수집 요청을 전송: 5회 400, 6회 429. 각 요청의 위조 X-Forwarded-For를 바꿔도 제한이 유지됨. 빈 요청이라 실제 수집 작업은 생성되지 않음.
- 브라우저에서 집계일이 보이는 화면 확인. 예: 요이 2026-09-26 / 테무인간 2026-10-13.

## 남은 개선 우선순위

1. 데이터 신선도: 정기 수집 목록은 21개. DB 키워드별 최신 기록은 10/13 21개, 9/26 28개, 9/15 1개, 8/19 5개로 나뉜다(숨김 키워드 포함 DB 전체). 현재 표는 날짜를 밝히지만 동일 날짜끼리의 순위는 아니다. 서비스가 “오늘의 인기”를 목표로 한다면 최신 집계 그룹을 별도로 보여주거나 정기 갱신 대상을 정리해야 한다. API 쿼터를 쓰는 전체 재수집은 실행하지 않았다.
2. 외부 공급자 오류: 최근 ‘줴줴이야’ 분석에 NVIDIA 504가 약 5분 후 발생한 기록이 있다. 실패 목록에는 과거 모델 종료(410)와 예전 크롤 실패도 섞여 있다. 현재 신규 생성의 안정성은 별도 실측이 필요하다. 수집 로그에는 나무위키·오늘의유머 차단과 Google Trends 429도 있다. 우회나 요청량 증가는 하지 않았다.
3. 결과 품질: 확인한 ‘요이’ 분석은 커뮤니티 글을 근거로 사용자층·확산 원인을 추정하며 거친 인용 표현도 남는다. 인구집단 추정과 유행 원인 서술은 근거 수준을 더 엄격히 구분할 필요가 있다.
4. 배포 재현성: 서버가 Git 없이 파일 복사 상태이므로 앞으로 커밋 ID 또는 배포 manifest를 함께 남기는 편이 좋다.
