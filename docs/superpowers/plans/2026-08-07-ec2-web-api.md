# EC2 웹 API 서버 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 RAG/분석/트렌드 파이프라인을 건드리지 않고 재사용하는 Flask 웹 API(`api/`)를 만들어, 웹사이트가 HTTP로 밈 질의응답/분석/트렌드를 조회할 수 있게 한다.

**Architecture:** `api/app.py`(Flask app factory + 동시성 제한 데코레이터 + 공통 에러 핸들러)와 `api/routes.py`(5개 엔드포인트: health/keywords/analyze/rag/trend) 2개 파일로 구성. 기존 `analysis/pipeline.py`, `analysis/rag_pipeline.py`, `trend/trend_service.py`, `embedding/encoder.py`는 그대로 재사용하고, 트렌드 실시간 호출을 캐시 호출로 바꾸기 위해 딱 2곳만 수정한다(`trend_service.get_cached_trend` 신규 추가, `analysis.pipeline.build_prompt`에 `trend_info` 파라미터 추가).

**Tech Stack:** Flask 3.1(이미 의존성에 있음) + flask-cors + gunicorn(리눅스 전용, 배포용). 로컬 테스트는 Flask의 `test_client()`로 서버 기동 없이 검증.

## Global Constraints

- 동시 처리 상한: `/api/analyze`, `/api/rag`에 프로세스 전체 공유 세마포어 2개 슬롯. 초과 시 429.
- CORS: 전체 허용(`*`). 프론트 도메인이 정해지면 나중에 좁힘.
- 트렌드는 **실시간 조회 금지** — `trend_scores` 컬렉션 캐시만 읽는다(`get_cached_trend`).
- 에러 응답은 전부 `{"error": "메시지"}` 형태로 통일.
- 참고 스펙: `docs/superpowers/specs/2026-08-07-ec2-web-api-design.md`
- Python 버전 제약(기존 `pyproject.toml`): `>=3.11,<3.12`
- 테스트는 이 프로젝트의 기존 컨벤션을 따른다: pytest 없이 `def test_*()` + `if __name__ == "__main__":`에서 순서대로 호출 + 끝에 `print("ALL PASS ✅")`. 실행은 `PYTHONIOENCODING=utf-8 uv run python tests/test_X.py`.

```python
def get_cached_trend(keyword: str, collection=None) -> dict | None:
    """trend_scores에서 keyword의 가장 최근 날짜 판정 문서를 읽어 반환. 없으면 None.

    실시간으로 naver/kakao/google을 호출하지 않는다 — main.py가 크롤 사이클(2시간)마다
    이미 채워둔 값을 재사용한다. API가 방문자 요청마다 실시간 조회를 하면 pytrends 등
    레이트리밋이 빡센 외부 서비스에 EC2 IP가 차단될 위험이 있기 때문(모듈 docstring 참고).

    collection을 넘기면 그 컬렉션을 쓴다(테스트용). 생략하면 실제 Mongo trend_scores를 쓴다.
    """
    if collection is None:
        from DB.mongo_client import get_collection
        from config.config_cilent import TREND_COLLECTION

        collection = get_collection(TREND_COLLECTION)

    docs = list(collection.find({"keyword": keyword}).sort("date", -1).limit(1))
    return docs[0] if docs else None
```

```python
"""
app.py
Flask 앱 팩토리 + 동시 처리 상한 데코레이터.

동시성 제한 이유: EC2가 GPU 없는 버스터블 CPU 인스턴스이고, /api/analyze와 /api/rag는
요청마다 BGE-M3 임베딩(RAG만) + LLM 호출을 돌린다. 여러 요청이 동시에 몰리면 같은
인스턴스에 떠 있는 mongo/qdrant/크롤러 스케줄러까지 같이 느려질 수 있어, 자체 인프라
보호 목적으로 동시 처리 개수를 코드로 제한한다(사용자별 rate limit과는 목적이 다름).
"""
import threading
from functools import wraps

from flask import Flask, jsonify
from flask_cors import CORS
from werkzeug.exceptions import HTTPException

MAX_CONCURRENT_REQUESTS = 2
_semaphore = threading.Semaphore(MAX_CONCURRENT_REQUESTS)


def limited(view_func):
    """MAX_CONCURRENT_REQUESTS를 넘는 동시 요청은 즉시 429로 거절한다(대기 큐 없음)."""

    @wraps(view_func)
    def wrapper(*args, **kwargs):
        if not _semaphore.acquire(blocking=False):
            return jsonify({"error": "서버가 바쁩니다. 잠시 후 다시 시도하세요."}), 429
        try:
            return view_func(*args, **kwargs)
        finally:
            _semaphore.release()

    return wrapper
```

```python
@bp.route("/rag", methods=["POST"])
@limited
def rag_endpoint():
    data = request.get_json(silent=True) or {}
    keyword = (data.get("keyword") or "").strip()
    question = (data.get("question") or "").strip()
    if not keyword or not question:
        return jsonify({"error": "keyword와 question이 모두 필요합니다"}), 400

    search_query = build_search_query(keyword, question)
    dense_vecs, lexical_weights = encode_batch([search_query])
    points = search_relevant_chunks(keyword, dense_vecs[0], lexical_weights[0], is_relevant=True)
    if not points:
        return jsonify({"error": f"'{keyword}'에 대한 검색 결과가 없습니다"}), 404

    cached_trend = get_cached_trend(keyword)
    trend_info = format_trend_context(keyword, result=cached_trend) if cached_trend else ""

    prompt = build_rag_prompt(keyword, question, points, trend_info=trend_info)
    answer = analyze(prompt)

    sources = [
        {
            "title": point.payload.get("title") or "제목 없음",
            "url": clean_source_url(point.payload.get("url")),
        }
        for point in points
    ]
    return jsonify({"answer": answer, "sources": sources, "trend": cached_trend})
```

(`unload_model()`은 의도적으로 호출하지 않는다 — API 서버에서는 LLM이 원격 NVIDIA NIM이라 VRAM을 비울 필요가 없고, 오히려 다음 요청에서 BGE-M3를 다시 로드하는 비용만 생긴다. `embedding/encoder.py`의 `_model` 전역 캐시가 그대로 프로세스 안에 상주하며 재사용된다.)

변경 후 (2개 서비스로 분리):
```yaml
services:
  scheduler:
    build: .
    container_name: mimori-scheduler
    depends_on:
      - mongo
      - qdrant
    env_file:
      - .env
    volumes:
      - .:/app
      - /app/.venv
    restart: unless-stopped

  api:
    build: .
    container_name: mimori-api
    command: gunicorn -w 1 --threads 4 --timeout 300 -b 0.0.0.0:5000 api.app:app
    ports:
      - "5000:5000"
    depends_on:
      - mongo
      - qdrant
    env_file:
      - .env
    volumes:
      - .:/app
      - /app/.venv
    restart: unless-stopped
```

(`scheduler`는 `command`를 안 줬으므로 `Dockerfile`의 기존 `CMD`(scheduler/scheduler.py)를 그대로 쓴다. `api`만 `command`로 gunicorn을 override한다. `-w 1 --threads 4`: BGE-M3가 무거운 모델이라 worker(프로세스)를 늘리면 모델이 그만큼 중복 로드된다 — worker 1개 + 스레드로 동시 요청을 처리한다. `--timeout 300`: `analyze()`가 최대 3번 재시도하며 수 분 걸릴 수 있어 gunicorn 기본 30초 타임아웃으로는 정상 요청도 끊긴다.)
