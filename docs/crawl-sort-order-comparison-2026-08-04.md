# 크롤링 정렬 기준(인기/관련도/최신) 비교

> 작성 2026-08-04. `feature/data_update`.
> 방법: natepann/dcinside 검색 결과 URL 목록만 실제로 가져와 비교(Mongo 저장 없음, 전체 게시글/댓글은 미수집).
> 스크립트: `data_test/compare_sort_orders.py`, `data_test/fetch_sample_titles.py` (커밋 대상 아님)
> 표본: 키워드 2개("야르", "쌰갈") × 정렬당 최대 20건. **표본이 작아 경향성 확인용이지 통계적 확정은 아니다.**

## 0. 결론 먼저

**정렬 하나만 쓰면 안 된다.** 세 정렬(관련도/최신/인기)이 사실상 서로 다른 문서 집합을 반환한다 — natepann에서 세 정렬 모두에 동시에 등장한 문서는 **0건**이었다. 지금처럼 두 정렬을 조합(natepann: 인기+최신, dcinside: 정확도+최신)하는 것이 타당했고, **natepann은 관련도(PD)까지 포함해 세 정렬을 조합하는 게 더 나아 보인다** — 아래 이유 참고.

**부수 발견**: "야르"라는 밈 키워드가 무관한 실제 상품명("야르보불닭" — 라면류 상품)의 부분 문자열이라 관련도/최신 정렬 결과에 섞여 들어왔다. 크롤러의 `_is_relevant()`가 부분 일치라 이걸 못 거른다. 아래 §3 참고.

## 1. 정량 비교 — 정렬 간 중복이 거의 없다

### natepann (PD 관련도 / DD 최신 / HD 인기)

| 키워드 | PD | DD | HD | PD∩DD | PD∩HD | DD∩HD | 셋 다 겹침 | 합집합 |
|---|---|---|---|---|---|---|---|---|
| 야르 | 20건 | 20건 | 10건* | 6건(18%) | 2건(7%) | 3건(11%) | **0건** | 39건 |
| 쌰갈 | 20건 | 20건 | 20건 | 2건(5%) | 2건(5%) | 5건(14%) | **0건** | 51건 |

\* HD(인기)는 "야르"에서 10페이지를 넘겨도 10건밖에 못 채웠다 — 아래 §2 참고.

### dcinside (accuracy 정확도 / latest 최신)

| 키워드 | accuracy | latest | 겹침 |
|---|---|---|---|
| 야르 | 20건 | 20건 | **0건 (0%)** |
| 쌰갈 | 20건 | 20건 | **0건 (0%)** |

dcinside는 두 정렬의 겹침이 완전히 0이었다. `latest`는 검색 시점(2026-08-03~08-04, 즉 오늘/어제)의 글만 반환하는 반면, `accuracy`는 훨씬 넓은 기간(4~8월)에서 뽑아온다 — 둘이 원천적으로 다른 문서 풀에서 온다.

## 2. HD(인기)는 비용이 크다 — 날짜 컷오프와 충돌

natepann에서 "야르"를 HD(인기)로 수집할 때 로그:

```
페이지 1: 0개 수집, 10개 날짜 제외
페이지 2: 0개 수집, 10개 날짜 제외
페이지 3: 2개 수집, 8개 날짜 제외
...
페이지 10: 0개 수집, 10개 날짜 제외   ← 상한(CRAWL_MAX_SEARCH_PAGES=10)에 걸려 종료
```

10페이지를 다 써도 목표 10건(20건의 절반)을 겨우 채웠다. **인기순은 오래된 글일수록 추천이 누적돼 상위에 오르는데, 3년 컷오프(`CRAWL_MAX_AGE_YEARS`)가 그런 글을 계속 걸러내서 페이지를 훨씬 많이 넘겨야 한다.** "쌰갈"은 3페이지 만에 20건을 채웠으니 키워드마다 편차가 크다. 이건 즉, **HD 정렬은 요청 수(=크롤 시간, 서버 부하)가 예측 불가능하게 늘어날 수 있다는 뜻**이다.

## 3. 질적 비교 — 실제 제목으로 본 각 정렬의 성격

### natepann "야르"

| 정렬 | 날짜 | 제목 | 비고 |
|---|---|---|---|
| PD(관련도) | 08-03 | `짜파게티 + 후라이 vs 야르보불닭 + 반숙란` | **오염 — "야르보불닭"은 라면 상품명, 밈과 무관** |
| PD(관련도) | 07-30 | `야르보불닭 먹고자야지` | **오염 — 동일 상품명** |
| PD(관련도) | 07-27 | `야르보불닭 먹을까 말까` | **오염 — 동일 상품명** |
| DD(최신) | 08-03 | `짜파게티 + 후라이 vs 야르보불닭 + 반숙란` | 위와 동일 문서(PD와 겹치는 6건 중 하나) |
| DD(최신) | 07-29 | `남친vs남편, 고민하는 사이 이 남자는 다 말아줌` | 제목만 봐선 무관해 보임(본문에 있을 수도) |
| HD(인기) | 06-05 | `...야르하게 예뻐지는 법` | 밈을 부사처럼 쓴 용례로 보임(관련 가능성 있음) |
| HD(인기) | 07-23 | `너무 싫어서 질색팔색하는 카리나` | 제목에 키워드 없음(본문 매치로 추정) |

**중요한 발견**: 상위 3건(PD 관련도)이 전부 "야르보불닭"이라는 무관한 라면 상품 얘기다. `_is_relevant()`가 부분 일치라서 "야르보불닭"의 "야르"만 보고 통과시킨 것 — matching.py가 부분 매칭을 금지한 것과 똑같은 이유의 오염이 크롤러 관련성 게이트에도 그대로 있다는 뜻이다. **관련도(PD) 정렬 자체가 이 상품명 때문에 "야르" 키워드에서는 상위권이 통째로 오염돼 있을 가능성이 있다.**

| 정렬 | 날짜 | 제목 | 비고 |
|---|---|---|---|
| accuracy | 07-31 | `나 요즘 밤티랑 야르란단어 배웠어 개쩔지` | **직접적인 밈 용례 — 정확히 원하는 데이터** |
| accuracy | 07-19 | `차쇼프 야르 및 콘스탄티노프스카야 전선 상황` | **오염 의심 — 지명/인명 표기가 우연히 "야르"를 포함하는 것으로 보임(전쟁 관련 게시글)** |
| accuracy | 07-25 | `원조 야르와 요즘 야르의 차이` | **직접적인 밈 용례 — 밈의 변천사를 논하는 이상적인 데이터** |
| latest | 08-04 | `김쿠 기념 킹블 삼` | 제목에 키워드 없음(본문 매치로 추정) |

accuracy(정확도) 상위권은 밈을 직접 논하는 양질의 글("원조 야르와 요즘 야르의 차이")과, 완전히 무관한 지명 표기 오염이 섞여 있다. latest(최신)는 실시간성이 강하고("오늘/어제"만 나옴) 밈을 캐주얼하게 쓰는 표현 위주다 — 정보 밀도는 낮지만 "지금 이 밈이 실제로 어떻게 쓰이는지" 보여주는 데는 accuracy보다 낫다.

## 4. 정렬별 특성 요약

| 정렬 | 장점 | 단점 |
|---|---|---|
| **관련도/정확도** | 밈을 직접 설명·논의하는 글이 상위에 옴(정보 밀도 높음) | 부분 일치 오염(상품명 등)에 가장 취약해 보임 |
| **최신** | 실시간 용례 포착, 신선함 | 정보 밀도 낮음(짧은 감탄사성 글 많음), 제목만으론 키워드 안 보이는 경우 많음 |
| **인기** | 커뮤니티가 검증한 글(자연스러운 용례 반영 가능) | 날짜 컷오프와 충돌해 페이지를 훨씬 많이 넘겨야 함(비용 큼), 키워드와 관련 없어 보이는 결과도 섞임 |

## 5. 권장

1. **지금 조합(natepann 인기+최신, dcinside 정확도+최신)은 유지할 가치가 있다** — 정렬 간 중복이 0에 가까워서, 하나만 쓸 때보다 실url질적으로 커버리지가 넓어진다.
2. **natepann에 관련도(PD)까지 추가하는 걸 고려할 만하다** — 세 정렬 모두 겹침이 0건이라 관련도가 추가로 유니크한 문서를 가져온다(다만 §3에서 본 "야르보불닭" 오염 위험도 같이 들어옴 — judge가 문서 단위로 사후에 걸러줄 수 있으니 심각하지 않을 수 있음).
3. **HD(인기) 정렬의 비용 문제(§2)는 감수할 만한지 판단이 필요하다** — 페이지를 못 채우면 목표치보다 적게 수집되고, 서버에 더 많은 요청을 보낸다. 문제 삼을 정도면 인기 정렬의 예산을 줄이거나(예: 20개 중 5개만 인기에 배분) 아예 제외하는 것도 방법이다.
4. **"야르보불닭" 같은 상품명 오염은 크롤러 관련성 게이트가 아니라 judge(문서 단위, 이미 구현됨)가 사후에 걸러줄 몫이다.** 크롤러 단에서 완벽하게 막으려 하지 않아도 된다 — 단, 이런 사례가 있다는 걸 알고 있어야 judge 라벨셋 검증할 때 이 유형을 놓치지 않는다.
