# 프론트엔드 UX 개선 백로그 (2026-08-11)

비동기 전환(analyze/rag 폴링화) 배포 후 실사용 체감 피드백. 아직 구현 안 함 — 나중에 하나씩 처리.

## 사용자가 지적한 것

1. **검색창이 너무 단순함** — `KeywordSelector.jsx`: `<input list=...>` + 브라우저 기본 datalist뿐. 트렌딩/추천 키워드 없음, 정확히 일치 안 하면 바로 신규 수집으로 넘어감(오타에 취약).
2. **RAG 질문창이 일반 챗봇 같음** — "더 궁금한 게 있으세요?" placeholder만 있고 예시 질문 없음.
3. **대기 중 화면 변화 없음** — 백엔드가 진행 단계(임베딩/검색/생성)를 안 넘겨줘서 스피너+"분석 중..." 텍스트만 있음.
4. **대기 시간이 너무 김** — CPU 임베딩 + 대형 LLM 호출이라 구조적으로 느림.

## 코드 리뷰하면서 추가로 찾은 것

- 첫 방문자용 설명/예시 키워드 없음 — 빈 검색창만 있어서 뭘 쳐야 할지 모름
- 트렌드 게이지(`TrendGauge.jsx`) 라벨(소멸/감소/평상/유행중/핫함)에 대한 범례 설명 없음
- `SourceFilter.jsx`의 출처 필터가 내부 소스명(`tavily`, `dcinside`, `namuwiki`...)을 그대로 노출 — 일반 사용자가 이해 못 함
- **`KeywordManager.jsx`의 숨기기/완전삭제가 로그인 없이 누구나 가능** — 공개 사이트라면 권한 문제 검토 필요 (보안 성격, 우선순위 높게 볼 것)
- 분석/답변 하단 출처 링크가 그냥 목록 나열, 사이트 구분 아이콘 없음

## 논의된 개선 아이디어 (착수 전, 순서 없음)

- **가짜 단계 표시**: 실제 진행률 몰라도 "관련 자료 찾는 중... → AI가 답변 작성 중..." 식으로 몇 초 간격 문구 전환만 추가 — 코드량 대비 체감 개선 큼, 우선 추천
- **캐시 예열**: 새벽 배치 크롤 김에 인기 키워드를 미리 analyze해서 캐시를 채워두면 체감 대기시간 크게 감소
- **대기 중 트렌드 먼저 노출**: 트렌드 조회(`fetchTrend`)는 이미 빠르니, 분석 결과 기다리는 동안 트렌드 게이지라도 먼저 보여주기
- **RAG 예시 질문 칩**: 질문창 위에 "누가 주로 써요?", "언제 유행했어요?" 같은 클릭 가능한 예시 질문 추가
- **출처 필터에 아이콘 추가** — 논의 결과:
  - 구글 파비콘 서비스(`https://www.google.com/s2/favicons?domain=...`)로 실제 사이트 로고 불러오기 + 로딩 실패 시 이모지 폴백 (추천안)
  - 또는 이모지/일반 아이콘으로 대체(저작권 이슈 없음, 오프라인 안전)
  - `tavily`는 특정 사이트가 아니라 여러 블로그/뉴스를 긁는 검색 API라 대표 아이콘이 애매함 — "웹 검색"류로 따로 묶는 방안 검토
- 검색창에 트렌딩/추천 키워드 노출 (설계 필요, 백엔드 트렌드 데이터 활용 가능)
